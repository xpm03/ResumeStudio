# 实现与设计说明

## 页面与数据

首版只有一个工作台：模块导航、当前模块表单、PDF 纸张预览。桌面使用三栏，手机切换编辑/预览，模块导航收进抽屉。暖白背景与深绿强调色围绕写作任务设计，没有账号、营销落地页或无实际意义的统计卡。

`src/domain/resume` 定义 v1 数据模型、空白草稿、虚构示例、备份校验与排序。内容和 `design` 配置独立；四个模块保留稳定 ID，支持排序和隐藏，未填条目不进入文档。当前只管理一份工作草稿。

`src/features/editor` 负责表单；`src/storage` 负责持久化和文件下载。React 状态保存当前内容，不增加全局状态库。导入时从允许字段重新构造对象，不合并任意外部属性；先验证文件，再由用户确认替换，默认先下载当前备份。

草稿以 `resumestudio.draft.v1` 保存到 localStorage，输入后延迟 600ms 保存，页面隐藏时补写当前内容。整体替换立即保存。损坏数据暂停自动覆盖，先让用户下载原始数据或明确放弃；禁用存储和配额失败显示备份提示。

## PDF 生成与显示

`src/templates/ResumePdf.tsx` 是两款模板的共同文档结构。浏览器 Worker 使用 React-pdf 生成 PDF；输入后延迟 400ms 排版，只接收最新请求的结果，正在工作时保留最后一个待处理请求。导出按钮在新产物生成前禁用，避免下载旧内容。

预览通过 PDF.js 显示同一个 Blob，而非另一套 HTML 排版。PDF.js 按容器和设备像素比渲染 Canvas；下载直接使用原 PDF，仍保留文字与链接。预览加载和渲染失败提供重试。

中文断行采用零宽断行机会，保留普通英文单词，并避免在中文闭合标点前换行。长 URL 允许分段换行。每次改变此逻辑都必须重新检查导出文本和分页，不能只看编辑表单。

Vite 原生 JSX 读取 TypeScript 的 `react-jsx` 配置。本项目未启用 React Fast Refresh 插件，避免将依赖 `window` 的刷新代码注入共享 PDF Worker 模块。开发依赖提前预构建；端到端验收使用生产构建。

## 字体验证与性能取舍

固定来源版本的 Noto Sans SC 生成 400/700 两个静态 TTF 字重，改名为 ResumeStudio Sans，保留字符覆盖；许可证与来源散列位于 `public/fonts`，生成脚本位于 `scripts/prepare-fonts.py`。

技术验证发现：本机上相同字体的 WOFF 在 Fontkit 中解析/排版明显较慢，TTF 将独立短文本排版从秒级降到毫秒级。因此交付 TTF。代价是首次使用需加载约 21 MB 中文字体；浏览器缓存可改善后续访问，弱网冷启动仍需进一步优化。不要用删除生僻字覆盖来掩盖此问题。

PDF 和 PDF.js 分别在 Worker/延迟加载模块中，主表单无需等待 PDF 引擎启动即可输入。单份特别长的文档仍可能排版较久；首版使用条目与文本长度限制，并明确生成状态。

## 发布与验证

GitHub Actions 先运行数据测试、PDF 检验和真实 Chromium 工作流，再发布 `dist` 到 Pages。发布包仅含静态应用与开源字体，不包含本地归档、简历草稿或开发环境。

PDF 检查生成一页示例和四页中英混排长内容，核对文本、嵌入字体、A4 与页面边界，并输出 PNG 供目视检查。此类检查不能证明所有招聘系统均兼容，也不能代替真实用户投递前检查文件。
