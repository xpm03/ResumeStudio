# 首版之后可以独立贡献的小任务

先在团队内认领一项，避免多人同时重写编辑器。每项一个分支和 PR，说明实际解决的问题，附验证结果。不要直接推送他人的分支或修改他人提交署名。

## A. 手机预览体验

目标：优化窄屏下的缩放操作、触控尺寸和预览滚动。

- 主要目录：`src/features/preview/`、`src/styles.css`。
- 在 360px、390px 和 768px 检查编辑/预览切换与多页内容。
- 不改变 PDF 文档数据或生成逻辑；不把预览换成另一套 HTML 排版。
- 验收：按钮可点、无横向页面溢出、多页能滚动，附手机截图并运行 `npm run test:e2e`。

## B. 联系方式填写反馈

目标：为格式异常的邮箱与网址提供清晰、温和的填写提示。

- 主要文件：`src/features/editor/Fields.tsx`、`src/domain/resume/model.ts`。
- 不禁止用户临时输入未完成内容；错误反馈能关联到对应输入框。
- 继续限制导出链接协议，不允许 `javascript:` 或带凭据网址。
- 验收：合法/非法/空白输入均有检查；运行 `npm test` 与相关浏览器流程。

## C. 快速上手说明与易用性

目标：让第一次打开工作台的人更容易了解本地保存、JSON 备份与 PDF 导出。

- 可改 README、页面中的简短说明或新增一段清晰的使用步骤。
- 使用真实截图和虚构数据，不加入尚未实现的功能。
- 保持主界面简洁，不增加强制引导弹窗或营销内容。
- 验收：按新说明从空白完成一次编辑、下载、备份恢复；界面改动附截图。

## 交给 AI 助手的任务示例

```text
这是 ResumeStudio 开源简历工作台。请先阅读 AGENTS.md、Plan.md、
README.md 和 docs/architecture.md。我负责 contributor-tasks 中的任务 B。
请只处理该任务，保持现有数据格式、PDF 管线和界面风格，
先检查代码，再实施修改并运行必要测试。
不要修改其他人的贡献署名，不要提交个人资料或密钥。
最后总结改动、实际测试结果和已知限制，供我检查后提交 PR。
```

## 提交方式

1. 在 GitHub Fork `xpm03/ResumeStudio` 到自己的账号并克隆。
2. 从最新 main 创建任务分支，按 README 准备环境。
3. 完成修改、检查差异和实际测试，用自己的 Git 身份提交。
4. 推送自己的 Fork，向 `xpm03/ResumeStudio:main` 提交 PR。

仓库维护者评审后合并。贡献应是可审查的代码、测试或文档改进；避免空提交和仅修改名字的 PR。
